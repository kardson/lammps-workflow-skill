# Existing-potential reference evaluation

`tools/reference_metrics.py` is a local library, not an inference backend or CLI. `evaluate(references, predictions, requested)` compares explicit record lists. Required sample identity is `id`; predictions need status `SUCCEEDED`, exact species order and the requested labels. Failed/missing predictions, missing labels and mismatches remain in metric-specific coverage. Unknown or duplicate IDs are not silently merged; extra prediction IDs make the report partial.

Energy uses energy_eV, an explicit matching energy_reference string and a nonempty dft_group. It reports signed per-atom errors, grouped by DFT group, convention and full composition. No energy offset is inferred or fitted. A declared matching convention is caller-provided alignment, not evidence that arbitrary ML/DFT energy zeros are compatible. Forces use forces_eV_per_angstrom N-by-3 arrays and component metrics per species. Stress uses stress 3-by-3 plus identical stress_unit and stress_convention; this library performs no sign/order/unit conversion.

Reports distinguish complete metric coverage from METRICS_PARTIAL and always leave scientific_acceptance UNVERIFIED. Empty groups have no invented zero error. Failed inference cannot improve coverage by disappearing. Sample/metric failures need inspection before any aggregate is used. Component counts are not independent replicate counts or uncertainty estimates.

`tools/evaluate_reference.py --references REF.json --predictions PRED.json --metric energy --metric forces --output-directory NEW_DIR` reads existing artifacts only. Repeat --metric for distinct requested metrics; add --plot for an optional matplotlib PNG. Output includes evaluation.json and samples.csv with failures/partial results retained. Exit 0 means complete metric coverage, not scientific acceptance; 1 means partial metrics; 2 means invalid input/dependency/I/O failure. Existing directories are never overwritten; a plot failure may leave the already-written numerical artifacts.

Both JSON envelopes require schema_version=1, source_class (artificial_fixture/research_candidate/reviewed_reference), records, and record_type reference_dataset or prediction_dataset. Predictions additionally declare backend {kind: empirical/pretrained_ml/artificial_fixture, identity: explicit identity}. Research artifacts require provenance [{path,sha256}] (relative paths use the artifact directory) and per-reference/per-successful-prediction configuration_sha256. Configuration identity includes the chosen structure snapshot and ordering and must match between records; the caller supplies and preserves that mapping. Referenced files are checked against declared identities. The reviewed_reference label is a declaration, not acceptance authenticated by the tool.

JSON artifacts are limited to 64 MiB; this is a bounded dataset evaluator, not a trajectory reader. Units are carried by label field names; no hidden conversion occurs. The optional plot shows valid/required samples and per-species force component MAE, explicitly labeled with source class and partial status. It does not replace the numerical artifacts.

Actual reference preparation/acceptance, complete DFT setting/PAW identities, structure mapping, immutable prediction provenance and target scenario coverage remain separate requirements. The current private candidate inventory accepts no research reference samples automatically. Backend prediction and actual target-system evaluation remain pending. Empirical and pretrained ML predictions may use this same comparison format; no training is included.

`tools/lammps_prediction.py` supplies a non-launching `import_sample(sample, base)` adapter for existing static outputs. Each sample binds input/log/dump/execution files by hash, with an optional execution JSON pointer. It requires exit 0, one explicit literal units metal command, conventional final Step/Atoms/PotEng thermo with a loop marker, and one orthogonal Cartesian dump containing id/type/x/y/z/fx/fy/fz. Geometry, bounds, boundary, atom IDs and type mapping must match the explicit requested configuration within an explicit 0..1e-5 angstrom tolerance. Includes/jumps/clear, trajectories, triclinic cells, implicit atom mapping and other units are unsupported.

`configuration_identity` hashes canonical JSON of species, atom_ids, boundary, bounds_angstrom and positions_angstrom (coordinates normalized to floats). This scheme must be shared by the reference exporter and prediction request; a generic file digest is not interchangeable. Imports preserve FAILED samples with reasons. Missing energy_reference remains null, so imported model energy cannot be silently aligned to DFT. Files are bounded to 64 MiB each and rechecked after import. This adapter does not launch an engine, authenticate the model actually used from its filename, validate stress, or establish target physical accuracy. Fresh preparation is described below; execution uses a separate authorized site adapter.

`tools/import_predictions.py --manifest MANIFEST.json --output-directory NEW_DIR` provides batch import. The manifest requires schema_version=1, record_type=static_prediction_import, source_class, backend {kind,identity} and 1..10000 uniquely identified samples accepted by import_sample. It writes predictions.json (directly readable by evaluate_reference), import.json and samples.csv. Every sample is retained, including missing outputs and failed execution. Exit 0 means all imported, 1 partial, 2 invalid input/I/O. Paths inside a manifest use its directory unless absolute. Dataset provenance preserves the manifest and verified source identities. Backend identity remains declared provenance, not independent proof of the model used. Fresh engine preparation/execution is separate.

Evaluation reports include reference label availability independent of prediction success, declared prediction status accounting and the largest 100 observed energy/force errors with sample IDs and groups. Rankings are diagnostic, have no automatic acceptance threshold and do not remove samples. The full sample list/CSV remains available. Per-sample source provenance and configuration identity are retained alongside metrics.

Each import sample declares:

| Field | Meaning |
|---|---|
| id | Unique nonempty sample ID |
| configuration | species in reference order, atom_ids, boundary as three two-character dump flags, bounds_angstrom 3-by-2, positions_angstrom N-by-3 |
| configuration_sha256 | configuration_identity result, shared with reference record |
| type_order | Explicit unique type-to-element order |
| expected_step | Integer static snapshot step |
| maximum_atoms | Positive integer memory/count bound |
| geometry_tolerance_angstrom | Explicit finite tolerance from zero through 1e-5 |
| artifacts | input/log/dump/execution objects with path and sha256; execution may add pointer to its actual exit record |
| energy_reference | Optional explicit alignment declaration; absent remains unresolved |

`tools/prepare_static_prediction.py --config CONFIG.json --output-directory NEW_DIR` prepares a fresh run-0 candidate without inference. CONFIG declares schema_version=1, record_type=static_prediction_plan, id, provenance, source_class (artificial_fixture/research_candidate/reviewed_reference), configuration plus configuration_sha256, maximum_atoms, masses_amu, engine_profile_file and potential. potential declares kind (empirical/pretrained_ml), provenance, type_order, files [{source,target,sha256}], pair_style tokens and pair_coeff token rows. Empty files is valid for an explicitly parameterized native pair style; no cross terms or mixing are inferred. Relative sources use the config directory. Every potential file is bounded to 64 MiB and copied/verified intact under its safe target filename.

The candidate includes structure.data, in.static, plan.json, engine-profile.json, copied potential files and preparation.json. Atomic IDs and Cartesian values are read back after serialization. Only orthogonal atomic p/f boxes with explicit masses and in-box coordinates are supported; periodic upper-face positions are rejected rather than wrapped. The input uses metal units, literal supplied pair syntax, run 0 and an explicit Cartesian force dump; it does not integrate or relax. Potential syntax/physics and any external path tokens still require actual input review. Unresolved engine fields remain in the preparation receipt. A complete draft is neither compatible-runtime proof nor execution authorization. Use a separately bound/authorized engine attempt; import and evaluate its real outputs afterwards.

## Physical species representation

Reference records may declare `species_representation` as `ordinary_atoms`, `pseudo_atoms` or `unknown`. Preserve PAW/pseudo-species provenance when building references: an XML element label such as H is not proof that a surface passivant is ordinary H. Do not guess ordinary-atom status from an element list.

This comparison adapter does not map pseudo-atoms to ordinary model species. Explicit `pseudo_atoms` records remain in JSON/CSV, count as unavailable for requested metrics, and produce a partial result; they are not silently deleted or compared under ordinary element names. A different physical mapping needs a separately justified adapter and evidence. Merely changing the declaration is not such a mapping.

Missing declarations preserve legacy numerical diagnostics with `UNQUALIFIED_DIAGNOSTIC`, not physical reference qualification. `ordinary_atoms` is a declaration, never proof of PAW identity, target-domain suitability or scientific acceptance. Reports include per-sample domain status and aggregate representation counts. This check cannot detect metadata that an upstream exporter has omitted, so retain original source identities and qualification records.
