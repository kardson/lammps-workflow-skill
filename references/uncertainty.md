# Statistical uncertainty and sensitivity

Use `summarize_replicas.py` for explicitly independent replica-level scalars. Its Student-t interval is conditional on the supplied independence/approximate-normality basis. Adjacent frames are not replicas. One replica has no estimated SD, SEM or confidence interval. Seed/window/correlation evidence and actual method acceptance must accompany research conclusions; distinct seed numbers alone do not prove independence.

Research-output summaries require replica_evidence and an explicit observation_kind=independent_replica_scalar before intervals can be enabled. Evidence may also be requested for fixtures/upstream references. Each list item binds group (exact configured group-column string values), replica_id, run_id, seeds, seed_basis, window {start_ps,end_ps,source}, correlation_basis, metric_definition, unit and metric_source {path,sha256,pointer,value_tolerance}. A zero-duration window needs kind=snapshot. Seed roles use nonnegative integers or explicit not_applicable with a justification; unresolved values remain a gap. Metric paths use the scalar CSV directory unless absolute; JSON evidence is limited to 16 MiB. The selected JSON scalar must match the CSV value within the explicitly supplied tolerance.

Missing evidence, changed/wrong scalar sources or repeated actual run IDs within a group retain all rows/mean/descriptive spread but withhold SEM/intervals and report REPLICA_SUMMARY_PARTIAL. They do not prove scientific comparability of input scalars. Distinct run/seed declarations are not authenticated independence evidence. Legacy fixture/upstream configurations without evidence keep conditional intervals based on their stated independence_basis, with LEGACY_DECLARED_ONLY labeling. Unknown/duplicate extra evidence identities are rejected rather than silently ignored. Single replicas remain descriptive only. Native JSON/CSV retain evidence/interval status; CLI exit 1 means unresolved evidence, 2 input/dependency/I/O error, 0 completed conditional/descriptive summary, never scientific acceptance.

`tools/summarize_time_series.py --csv SERIES.csv --config CONFIG.json --output-directory NEW_DIR` adds within-run diagnostics. It writes native blocks.csv and time-summary.json, never launches a calculation or selects equilibration automatically. The input is streamed and only running moments/adjacent block-pair state are retained; explicit maximum_blocks bounds the block output count. Source identity is checked before/after analysis. Failed data leave labeled partial artifacts, not empty valid metrics.

CONFIG explicitly declares time_column, metric_column, unit, run_id, source_class (engineering_fixture/upstream_reference/research_output), seeds object and seed_basis. Unknown seed values remain null and are reported. Sampling fields are window_start_ps, window_end_ps, window_basis, sample_interval_ps, time_tolerance_ps, block_duration_ps, maximum_blocks, minimum_blocks_for_interval (>=2), confidence, stationarity_basis, correlation_basis and max_absolute_block_lag1 (0..1 or null). No numeric scientific defaults are supplied; the draft template is not runnable until values are chosen.

The sample window is half-open [start,end). Times must be strictly increasing and match the declared cadence within the declared tolerance (less than half an interval). Block duration contains an integer number of intervals. Empty/missing-sample or terminal partial blocks are preserved and withhold an interval. Raw sample mean/SD are descriptive, not an IID-frame SEM. Complete-block mean dispersion is recorded separately.

A conditional Student-t interval uses complete block means only, their count and the declared confidence. It is withheld unless all blocks are complete, the minimum count is met, stationarity/correlation bases are explicit, a lag-1 diagnostic is available and it meets the supplied limit. At least three adjacent complete-block pairs are needed for that diagnostic; pairs never bridge missing blocks. This is a sanity check, not proof of independence or higher-lag decorrelation. Block duration and physical sampling-window adequacy still require a separate scientific justification; temperature stability alone does not provide it.

Exit 0 means a conditional interval was reported, 1 descriptive-only or failed evidence, 2 initial input/I/O/usage failure. Scientific acceptance always remains UNVERIFIED. Missing bases/diagnostics leave SD/mean available with no fabricated SEM or interval. Model discrepancy, finite-size effects and timestep/flux/geometry sensitivity are not contained in these statistical error bars.

Sensitivity work continues to use explicit bounded variants through prepare_sweep.py. Associate every change with its base plan, purpose and reason; preserve separate size/timestep/flux/model hypotheses. A candidate list is not permission to run it. No automatic grid search, parameter repair, model switching or training occurs. A research sensitivity design, replica evidence linkage and acceptance thresholds remain separate from these statistical helpers.

`prepare_sweep.py --config CONFIG --maximum-candidates N --output-directory NEW_DIR --plan-only` can organize proposals before a base model is complete. It validates the existing atomic-beam variant keys, safe IDs, explicit budget, purpose/reasons and optional plan identity, then writes only sensitivity-plan.json. No structure/potential/input package is generated, and no job is submitted. Variants may retain null parameter values; comparison_basis, sampling_window and replica_strategy gaps remain explicit. Ordinary preparation without --plan-only still uses the original candidate generator and its readiness checks. Potential/model changes outside that generator's supported keys need a separate explicit plan, not a hidden mutation. Proposals do not modify the base configuration or authoritative scientific plan.
